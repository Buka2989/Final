# Подготовка к защите Arena ID

## Короткое описание темы

**Arena ID — Clash Royale Personality Quiz.** An interactive website that matches a user's everyday choices with one of eight Clash Royale personalities. The project includes a 12-question quiz, a character catalogue, live search, form validation, and saved progress.

Это можно использовать как описание идеи в таблице преподавателя. Имена и группу впишите свои; уникальность темы необходимо проверить в самой таблице.

## Демонстрация на 4–5 минут

1. **Главная, 30 секунд.** Объяснить идею, показать четыре страницы и единое оформление.
2. **Тест, 2 минуты.** Попробовать пустое имя и переход без ответа, затем выбрать ответ. Перейти дальше и вернуться. Обновить страницу и продолжить сохранённый тест. Завершить все вопросы.
3. **Результат, 40 секунд.** Объяснить четыре шкалы, ближайший профиль и стабильность результата. Скопировать текст.
4. **Каталог, 40 секунд.** Ввести `wizard`, выбрать `Thinker`, получить 2 карточки. Показать пустую выдачу, сброс и модальное окно.
5. **Адаптивность и код, 1 минута.** Сузить окно, открыть мобильное меню, показать JSON и две функции из `scoring.js`.

Перед демонстрацией запустите локальный сервер. Открывать HTML напрямую нельзя из-за загрузки JSON. В папке `assets/vendor` находятся настоящие Bootstrap и jQuery, поэтому интернет не нужен.

| Технология | Пример | Что объяснить |
|---|---|---|
| HTML5 | `main`, `section`, `article`, `nav`, `form`, `fieldset`, `legend` | Семантика и структура документа |
| CSS3 | `assets/css/style.css` | Переменные, flex, grid, псевдоклассы, медиазапросы, состояния фокуса |

| JavaScript | `scoring.js` | Массивы, функции, reduce, map, sort, проверка входных данных |

## Объяснение состояния теста

```js
state = {
  nickname: 'Player',
  index: 0,
  answers: [null, null, null, null, null, null, null, null, null, null, null, null]
};
```

`index` — текущий вопрос, начиная с нуля. `null` — ответ ещё не выбран, а число `0` — полноценный первый вариант ответа. Поэтому нельзя проверять ответ выражением `if (!answer)`.

При выборе radio сохраняем номер варианта в `answers[index]`. При возврате показываем этот номер как `checked`. На финальном шаге передаём весь массив в функцию расчёта. Это исключает повторное начисление баллов при смене ответа.

## Пример расчёта

Пусть для двух вопросов выбраны векторы `[3, 0, 2, 1]` и `[0, 3, 2, 2]`. Сумма равна `[3, 3, 4, 3]`. Максимум по каждой шкале — `2 × 3 = 6`. После нормализации и округления получается `[50, 50, 67, 50]`.

Для персонажа с профилем `[65, 45, 95, 30]` расстояние равно:

```text
|50−65| + |50−45| + |67−95| + |50−30| = 68
```

Чем меньше расстояние, тем ближе профиль персонажа. Профили и веса придуманы для развлекательного проекта; это не научная модель личности.

## Возможные вопросы преподавателя

**Что такое DOM?** Дерево объектов, которое браузер строит из HTML. JavaScript и jQuery читают и изменяют его: например, заменяют текст вопроса и набор ответов.

**Чем `==` отличается от `===`?** Строгое сравнение `===` не приводит типы. Например, `0 === '0'` — false. Значение из radio сначала превращаем в число через `Number()`.

**Почему используется `preventDefault()`?** Чтобы форма не перезагружала страницу. Вместо стандартной отправки выполняется наша валидация и переход к следующему шагу.

**Что такое делегирование событий?** Обработчик устанавливается на постоянный родительский элемент, например `#answer-options`, и реагирует на события его динамически добавленных `input`. Не нужно заново назначать обработчики после каждого вопроса.

**Зачем JSON?** Это формат хранения данных. Содержание вопросов можно изменить отдельно от кода их отображения. `$.getJSON` асинхронно загружает файл через HTTP.

**Чем localStorage отличается от переменной?** Переменная исчезнет при перезагрузке. localStorage хранит строки между посещениями одного origin. Для объектов используем `JSON.stringify` и `JSON.parse`. Другой порт или браузер — другое хранилище.

**Почему есть try/catch?** JSON в хранилище может быть повреждён; браузер может запретить сохранение или Clipboard API. Ошибки обрабатываются, чтобы интерфейс не переставал работать.

**Почему `.text()` безопаснее `.html()` для никнейма?** `.text()` вставляет обычный текст. `.html()` интерпретирует разметку. Перед вставкой динамических строк в HTML используется `escapeHtml`; формат никнейма также проверяется.

**Как работает адаптивность?** Bootstrap меняет число колонок на своих breakpoints; собственные медиазапросы корректируют отступы, шрифты, расположение кнопок и иллюстраций. `meta viewport` задаёт правильный масштаб на телефоне.

**Что сделано для доступности?** Настоящие кнопки и radio, label для полей, alt для изображений, fieldset/legend, видимый фокус, skip link, сообщения об ошибках, ARIA-состояния и reduced-motion. Только цвет не используется как единственный признак выбранного ответа.

**Где используется jQuery, а где обычный JavaScript?** jQuery загружает данные, подписывается на события, читает поля и обновляет DOM. Чистый JavaScript рассчитывает профиль, сортирует персонажей и работает с Browser API.
